# דשבורד הרכש החברתי של המדינה

שני לוחות בקרה עצמאיים לעבודה על הרכש החברתי הממשלתי:

1. **[הוצאות הרכש החברתי](dashboards/expenditure.html)** — על מה מוציאים, אילו משרדים, כמה, וכיצד מתחלקת ההוצאה. מבוסס על נתוני אתר "מפתח לרכש חברתי" (`socialpro.org.il`).
2. **[הצד המכרזי של הרכש](dashboards/tenders.html)** — כמה מהרכש יוצא בפטור ממכרז, בספק יחיד, ואיזה מסלול ועדות נדרש לכל התקשרות. מבוסס על אתר מנהל הרכש הממשלתי (`mr.gov.il`).
3. **[דשבורד רכש חברתי — גרסה מאומתת](dashboards/social_procurement_verified.html)** — לוח בקרה מקיף יותר (תמונת מצב תקציבית, פטורים ומכרזים, מפעילים וריכוזיות), שפותח בנפרד ומבוסס על קובצי נתונים אמיתיים שאומתו ידנית, ולא על אומדן להמחשה כמו שני הקבצים הקודמים. ראו "סטטוס נתונים" בהמשך לגבי ההבדל בין שלושת הקבצים.

כל קובץ הוא עמוד HTML עצמאי (ללא תלות בשרת) — ניתן לפתוח אותו ישירות בדפדפן.

## סטטוס נתונים — חשוב לקרוא לפני שימוש

בסביבת העבודה שבה נבנה הפרויקט, מדיניות הרשת חסמה גישה לכל אתרי המקור הרלוונטיים (`socialpro.org.il`, `mr.gov.il`, `data.gov.il`, `gov.il`, `next.obudget.org`). כתוצאה מכך:

- **לוח ההוצאות**: הסך הכולל (17.4 מיליארד ₪, 2024), החלוקה בין שלושת המשרדים החברתיים (רווחה 7.7 מיליארד ₪, בריאות 6.7 מיליארד ₪, חינוך 3.1 מיליארד ₪), מספר השירותים (232) ומספר המפעילים (1,002) מבוססים על נתונים פומביים שאותרו בחיפוש (דיווחי `gov.il` ותקשורת כלכלית על בסיס אתר מפתח לרכש חברתי). כל שאר הפילוחים בלוח — מגמת שנים, סוגי מפעילים, פירוט שירותים לפי משרד — הם **אומדן להמחשה** בלבד, ומסומנים ככאלה בממשק (תג "≈ אומדן").
- **לוח המכרזים**: אין ברשותי נתונים כמותיים אמיתיים על שיעורי פטור, ספק יחיד או זמני טיפול. הדבר האמיתי שאותר הוא שתקנה 3(1) לתקנות חובת המכרזים (פטור בשל סכום התקשרות נמוך, עד 50,000 ₪) היא עילת הפטור הנפוצה ביותר בפועל, וכי לפי דוח מבקר המדינה מערכת "מנוף" שדרכה משרדי הממשלה מפרסמים בקשות פטור **אינה ידידותית למשתמש ואינה מאפשרת ייצוא נתונים לניתוח**. כל שאר הנתונים המספריים בלוח זה הם אומדן להמחשה, ומסלול האישורים (ועדת פטור מוסדית ← ועדת פטורים מרכזית ← שר האוצר) מתואר ברמה עקרונית בלבד ודורש אימות מול הנוסח העדכני של תקנות חובת המכרזים וחוזרי החשכ"ל.
- **דשבורד רכש חברתי — גרסה מאומתת**: בניגוד לשני הקבצים שלעיל, קובץ זה פותח בסשן נפרד תוך גישה בפועל לשני קבצי יצוא אמיתיים ממנהל הרכש הממשלתי (רשומות פטור ורשומות מכרז פומבי, 20.09.2026), ולנתוני תקציב מאושר ומבוצע אמיתיים ברמת משרד ושנה. כל מספר המתויג בממשק כ-"✓ מאומת" נבדק ישירות מול שדה מתאים בקובץ המקור, כולל מספרי התקנה המדויקים שעליהם יושבת כל עילת פטור. קובץ היצוא הגולמי עצמו (כקובץ XML בשם xls, במשקל של כ-478 מגה-בייט) לא הוכנס לריפו הזה משום שהוא חורג משמעותית ממגבלת הגודל המקובלת להעלאת קובץ בודד ל-GitHub; הוא קיים כרגע רק בסביבת העבודה הזמנית שבה נבנה הקובץ. מי שירצה לשחזר את תהליך האימות או לבנות מחדש את הצבירות (לדוגמה כדי להוציא רשומות "כוונת התקשרות" מהספירה לפי עילה) יצטרך לקבל את קובץ המקור הזה מחדש, ואפשר לשקול החסנה שלו דרך Git LFS או כקובץ JSON מצומצם של הצבירות הגולמיות בלבד.

כל תא נתון בממשק מסומן בתג אחד משלושה: `✓ מאומת` (נתון עם מקור פומבי), `≈ אומדן` (המחשה בלבד, לא נתון מדווח), או `⚖ מסגרת כללית` (עיגון משפטי/מבני שיש לאמת מול הנוסח המחייב העדכני).

## מבנה הנתונים

הנתונים חיים inline בתוך כל קובץ HTML (בתוך בלוק ה-`<script>`, באובייקטים כמו `ministries`, `trend`, `exemptReasons` וכו'), כדי לשמור על כל דשבורד כקובץ עצמאי אחד. כדי לעדכן נתון — לערוך את האובייקט המתאים בקובץ הרלוונטי.

## איך להשלים עם נתונים אמיתיים

### לוח ההוצאות (מפתח לרכש חברתי)

אתר `socialpro.org.il` (ו-`next.obudget.org`) חושף גרפים מצרפיים ורשימת מידע גולמי לכל משרד. מומלץ:
1. לבדוק אם קיים API או ייצוא CSV/JSON ישירות מהאתר (יש לבדוק את בקשות הרשת בדפדפן בעת גלישה באתר).
2. אם אין ייצוא ישיר — לבנות סקריפט חילוץ (Python + `requests`/`playwright`) שעובר על עמודי כל משרד ומייצא טבלת שירותים ברמת גרנולריות של שירות בודד (משרד, שם שירות, סכום, מפעילים).
3. להזין את הפלט לתוך אובייקטי הנתונים ב-`dashboards/expenditure.html` (או, אם נפח הנתונים גדל, להפריד לקובצי JSON נפרדים שהעמוד טוען).

### לוח המכרזים (מנהל הרכש הממשלתי)

זהו המקרה שבו נדרש **agent ייעודי**, כפי שצוין בבקשה המקורית — הנתונים אינם מרוכזים או ניתנים לייצוא, ולכן נדרשת עבודת חילוץ ונרמול:

1. **מיפוי המקור**: לזהות היכן בדיוק מתפרסמות בקשות/החלטות פטור באתר `mr.gov.il` (למשל מערכת "מנוף" או פרסומים ייעודיים), כולל פורמט הפרסום (HTML טבלאי, PDF סרוק, מסמכי Word).
2. **חילוץ**: agent שעובר על הפרסומים (Playwright לדפדוף, OCR/parsing ל-PDF במידת הצורך) ומחלץ עבור כל בקשת פטור: משרד מזמין, סכום, עילת הפטור (סעיף בתקנות), ועדה מאשרת, תאריך אישור.
3. **נרמול**: איחוד לטבלה אחידה, כולל טיפול בשונות בפורמט בין משרדים ותקופות.
4. **סיווג לפי עילה**: מיפוי כל עילת פטור לקטגוריה קבועה (סכום נמוך / ספק יחיד / דחיפות / ביטחוני / אחר) כדי לאפשר את גרף "עילות הפטור" בלוח.
5. **הזנה ללוח**: עדכון אובייקטי הנתונים ב-`dashboards/tenders.html` בהתפלגויות האמיתיות שיתקבלו.

לאור מדיניות הרשת החוסמת בסביבת העבודה הנוכחית, שלב זה לא בוצע כאן ודורש הרצה מסביבה עם גישה לאתר (למשל סביבת עבודה מקומית, או סביבת Claude Code עם מדיניות רשת רחבה יותר).
